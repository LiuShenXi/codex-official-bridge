# Codex 桌面兼容改造

2026-09-16，用户明确要求改造服务端，主要使用场景为官方 Codex 桌面版。该要求取代首版仅服务自写函数示例客户端的范围。

## 目标

桌面二号保留官方客户端、原生工具、本地项目和本地执行流程，通过独立 provider 的地址与网关密钥访问服务端。上游账号只在服务端登录。工具定义、角色历史、加密推理数据及流事件不改写为普通函数或提示词。

## 必须调整的实现边界

现有 `thread/start.dynamicTools` 路线保留为基础演示，不能作为桌面生产请求的执行器。桌面已有 Agent 回合控制；服务端应提供单次模型协议通信，不再创建第二个会自行处理工具的 Agent 回合。

新方案采用锁定版本的官方 Codex 认证与 HTTP 通信库构建专用服务端运行时。它属于基于官方源码的扩展，不等同于原封不动的官方 CLI，也不保证隐藏分发行为或解除账号限制。当前来源版本：`rust-v0.154.0-alpha.6.2`，commit `b5bffd3ec4db487e7e3dec59663875b0ef7b72ca`。

## 首个验收闭环

1. 真实官方客户端发送原生 custom grammar 工具定义与完整历史。
2. 服务端按原始字节保留 Responses 请求体；不删除未知模型字段，不解析重排 JSON。
3. 上游原生 custom 工具调用到达客户端，客户端实际修改临时项目文件。
4. 客户端将原始工具结果和历史继续发送，模型正常完成；不在服务端执行该工具。
5. SSE 的事件与字段、加密推理内容、usage 和错误响应保留；断连能终止上游传输。
6. `/v1/responses/compact` 与允许查询参数的 `GET /v1/models` 采用同样的透明数据通路；未知路径拒绝，不能把服务做成任意 URL 代理。
7. 桌面二号修改前私有备份配置；只修改二号独立配置，不影响当前一号。
8. 官方桌面实际任务验收与同内核 CLI 合同验收分开记录，不能用 CLI 成功冒充已完成桌面 UI 测试。

## 改动位置

- `native-runtime/`：官方认证、上游连接、原始流转发；不包含 Agent 或工具执行器。
- `src/native-runtime.mjs`：私有运行时启动、就绪、退出与内部鉴权。
- `src/server.mjs`：复用现有鉴权入口，新增原生字节转发路径，保留旧模式测试。
- `src/main.mjs`、`src/runtime.mjs`：显式选择运行模式，传递已隔离的环境。
- `scripts/verify-desktop-contract.mjs`：真实官方客户端执行原生工具的离线合同验收。
- `test/`：字节与事件保真、HTTP 错误、压缩体、取消、compact 和凭据边界回归。
- `scripts/` 与文档：锁定源码/构建入口及二号配置流程。

本轮优先完成单账号桌面工作流；多账号调度、多人权限与公共部署在该闭环通过后再处理。

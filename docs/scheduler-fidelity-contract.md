# 调度改动的出站一致性合同

日期：2026-09-18。状态：验收设计，未执行新一轮真实抓包。配套[主设计](scheduler-design-v1.md)与[状态控制合同](scheduler-control-contract.md)。用户要求沿用现有runtime，并保持已验证的出站一致性；新增调度不能破坏该基线。

## 1. “一致”的判据与比较对象

必须同时保留三种比较，不能互相代替：

| 比较 | 回答的问题 | 硬判据 |
| --- | --- | --- |
| 同一操作：框架入口A → Rust官方出口B | 调度是否改写客户端原始内容 | 请求实体字节/WS应用消息相同，未知字段、顺序及工具/历史内容保留；身份和逐跳头单独核验 |
| 官方客户端直连C → 框架出口B的可比用例 | 出站是否符合该固定官方版本的请求合同 | 对相同逻辑输入与配置核对方法、路由、语义头、模型/工具/历史/编码；仅允许事先列明并有证据的身份/动态/逐跳差异 |
| 调度加入前B0 → 加入后B1 | 调度是否引入额外变化 | 相同fixture与版本条件下，无未列明的新内容/头部差异；发送次数和目标受明确调度规则约束 |

“与旧runtime一样”不能替代官方直连对照；“解析后JSON相同”也不能替代同操作原始字节相同。对两次独立生成的答案不要求相同；响应保真比较的是同一上游响应经过框架前后，不能用两次不同模型输出判断转发改写。

用户此前确认的一致性结果作为历史基线保留，不宣称被推翻。发布清单必须引用具体报告/批次/版本/覆盖范围后才能继承该结果；尚未纳入清单的历史口头结论记 baseline_pending，不替新路径打勾。本次没有解密真实采集正文或重跑生产实验。

## 2. 不得变化、必要变化与未覆盖项

| 对象 | 验收规则 |
| --- | --- |
| HTTP原始请求正文 | A→B逐字节一致，包括压缩字节；不parse后stringify、不重新压缩、不重排字段、不清理历史ID |
| WS应用消息 | 逐条payload及顺序一致；含metadata、未知字段、previous_response_id、加密上下文、工具调用/结果；不新增调度字段 |
| 模型语义 | model、reasoning、tools/custom grammar、instructions/input、store/include、压缩上下文、客户端turn state均不可静默改写 |
| 任务/会话标识 | 该官方版本已有的thread/session/metadata按合同保留；不得为轮询账号生成新session；内部task/lease/attempt信息只走私有控制通道 |
| 认证身份 | 框架入口Key不得泄漏到上游，使用已绑定真实账号的认证及账号头；与该账号官方认证规则核对。不同账号或刷新后的秘密值不要求相等，也不得在报告展示原值 |
| Host/路径/逐跳头 | 按入口→固定官方目标的精确映射检查；Connection、Content-Length、WS握手派生字段等由各链路协议处理，逐项记录，不以“代理原因”忽略所有headers |
| 客户端标识/能力头 | 与固定版本官方直连核对；不能为伪装客户端凭空添加头。未知增删/覆盖一律报告并阻断对应验收 |
| HTTP响应/SSE | 同一响应的状态、语义头、原始实体字节和事件顺序保留；不添加心跳注释、不伪造completed、不替换流内错误 |
| WS响应 | 同一上游应用消息原样转发；握手、控制帧、压缩协商和close语义分别验收，不能把payload相同说成线缆帧相同 |
| 排队/取消/失败时序 | 调度会延迟发送、拒绝准入；独立observer可能延后close。必须有单独场景合同和实际证据，不能声称这些时序与直连完全一样 |
| TLS/TCP/HTTP2线缆行为 | 现有中间人采集不证明原始TLS指纹、TCP分段、HTTP2帧、连接复用和重试全生命周期等价；标记未覆盖，不合并到应用一致性PASS |

差异白名单按字段路径、方向、触发条件和版本固定，并附理由/断言。例如WS Sec-WebSocket-Key两次连接的随机值本就不同，验证其协议合法性；不能把整个握手移出对照。Authorization以账号归属和授权方式校验，不显示密钥；不能顺便忽略chatgpt-account-id不匹配。任何影响模型/工具/历史内容的差异不得加白名单以凑通过。

动态值只有在证明确实为本次运行生成的标识后，才能在C↔B比较中建立一一对应映射。映射须验证整个续聊/分支生命周期及交叉引用，不得全局删除所有名为id的字段。A→B是同一请求，不使用这种归一化掩盖变化。

## 3. 采集与因果配对

A为已鉴权框架入口，B为该请求实际选中worker的官方出口，C为固定版本官方客户端直连出口。记录版本、配置、协议、fixture、账号匿名指纹与出口匿名引用；模型正文/凭据只在受控加密档案中，公开报告只保留必要摘要和差异类型。

同请求A→B优先通过框架私有trace/request/attempt映射及独立连接/消息序号配对；不能为了配对在上游正文/头插入追踪标记。既有响应ID可辅助证明已完成请求的因果关系；用户提示词hash和出现顺序只提供候选，不能独立证明。同任务可能有多次模型操作和401 attempt，不按thread-id把它们合成一次。

C↔B使用版本固定、工具目录/权限/工作目录/上下文一致的可重复用例，并记录差别；未控制的两次交互实验只能报告观察。真实账号比较不得复制活动refresh token制造两个认证维护者；采用隔离测试身份或有序接管，真实测试方案单独准备，本次不操作。

每个被判定的比较单元必须有完整原始记录、认证解密通过、序号完整、请求/响应或操作终态，以及采集批次正常封存。记录截断、WS关闭/流错误、缺终态和配对歧义均写入结果；活动会话中间快照不得当最终“完全一致”。

压缩原文与解码结果分别保存/比较。解码失败是UNVERIFIED或FAIL，不是“没有差异”。计时用采集点内部单调时钟；跨主机绝对时间不直接相减。TLS代理改变握手对端、缓冲和时序，其观察范围见[采集工具说明](../scripts/request-capture/README.md)。

## 4. 发布验收矩阵

| 用例 | 同操作内容检查 | 调度检查 |
| --- | --- | --- |
| 首请求HTTP及WS | 字节/应用消息、语义头、模型/工具 | 登记、绑定、准入先于上游发送 |
| 工具调用与回传、多轮续聊 | custom grammar、原始历史、响应链不改 | 同账号，每轮重新准入 |
| compact与压缩后续聊 | gzip/zstd等原始数据、旧/新压缩路径及opaque内容 | 同账号，不能把压缩视作新任务 |
| fork/resume/重连 | 父来源、thread、metadata按固定合同 | 持久账号归属不变；严格池未知来源拒绝，固定入口按受限来源合同记录，身份缺失/来源冲突同样拒绝 |
| WS预热及后续生成 | generate:false原样保留，真实终态合同 | 预热无旁路；空闲连接不占生成 |
| 队列等待后发送 | 等待前后原始内容摘要相同 | 只发一次到原账号；截止未发 |
| 401恢复/429/5xx/200流内失败 | 每attempt及错误来源可追踪 | 除已验证401外无框架隐形重放 |
| WS错误→HTTP回退 | 客户端自行变形作为新网络尝试单列 | 同任务障碍生效，未知操作额外发送0次 |
| 取消/断连/慢读 | 未完成交付明确记录，终态不伪造 | 有界observer，不按close或TTL消债 |
| 并发与进程重启 | A/B/capture关联不混串 | 无跨号、无重复许可、无丢绑定 |
| 图片/大帧/未知字段 | 支持路径原始内容不变，不截断 | 共享容量、内存有界；不支持明确拒绝 |
| 出口故障/维护 | 没有非预期目标、身份和出口变化 | 不直连回退、不换号，已有任务保留归属 |

离线层先运行现有HTTP/WS保真测试、真实core+本地mock、正式Rust发送边界fixture，覆盖用户正文之外的未知字段和压缩。官方直连真实采集属于另一层，不能用Node→mock测试充当完整Rust出口验证。所有层结果分别展示。

每轮输出版本化 manifest：baseline_id、源码/二进制hash、客户端/协议profile、采集器版本、自检结果、用例、关联记录索引、采样完整性、匹配依据、允许差异规则版本、全部未解释差异、分层结论。结果至少分 BODY_BYTES、APP_MESSAGES、HEADERS、ROUTING、FAILURE_BEHAVIOR、TRANSPORT_OBSERVABILITY；不得一个绿色总分隐藏缺项。

未知内容改写、错误账号/出口、未准入发送或不可解释额外attempt为阻断项。新增字段/未知协议路径先限于测试profile；不得自动扩展白名单。采样不完整或没有C对照时，只能给已覆盖层通过，其余UNVERIFIED；不能对外称“已与官方直连全面一致”。

历史三点A/B/C最终报告仍需与具体批次/hash关联后纳入发布台账。本次设计延续既有验证成果，但不把Sub2API对照或采集工具自检误称为该三点对照。实现M0时完成台账，M1/M2每次改变发送路径重新运行对应矩阵；管理后台外观调整不要求重复模型实验。

发生回归时停止发布该版本、保留差异证据，修复后再验证；已运行任务不因回滚而迁移账号。生产发布需兼容数据库迁移、排空和原绑定，不能以删除数据库恢复运行。

抓包默认是隔离验收工具，不是长期生产明文日志。采集有时间/磁盘上限、加密和清理策略，凭据/正文不进入调度决策日志。降低额外变化以这些可测指标说明，不把“采样一致”转换成未经验证的账号风险承诺。
